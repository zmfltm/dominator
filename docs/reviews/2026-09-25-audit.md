# Quick code audit, 2026-09-25

Reviewed the download, validation, metadata, preview, SoundCloud, progress,
process, API and server modules, frontend queue/clip/download behavior, tests,
and startup/container configuration. This was a static review with targeted
runtime checks, not a full security assessment.

## Fixed

- `src/app.ts`: the 16 KiB request limit only checked Content-Length. Requests
  without that header could bypass it. Hono's body-limit middleware now checks
  streamed bodies too. Regression tests cover absent Content-Length and chunked
  transfer encoding.
- `src/metadata.ts`: JSON `null` from yt-dlp could throw while accessing `title`
  in the subprocess close callback. Non-object metadata now returns the existing
  invalid-metadata result. Regression tests cover null, arrays, and primitives.

## Follow-ups

- Medium, `src/jobs.ts`: download and clipping processes have no wall-clock
  timeout. Hung processes can occupy all seven slots until canceled or the app
  restarts. Metadata and previews already have timeouts. Add a configurable
  download deadline with process-tree termination.
- Medium, `public/index.html`: canceling a row while POST /api/jobs is pending,
  then immediately retrying, can allow the old response to overwrite the retried
  row's job ID. Use an attempt token and cancel stale responses' job IDs. This
  was identified by tracing state transitions; no timing-based reproduction was
  performed during this quick pass.

## Discord support and checks

Direct HTTPS audio/media attachment links on cdn.discordapp.com and
media.discordapp.net now queue as MP3. Signed query strings are preserved.
Message links return instructions to copy the audio attachment URL instead.
Existing local binding, host allowlisting, and subprocess argument boundaries
remain in place.

- 105 tests pass; TypeScript checking and whitespace checks pass.
- Browser check: a Discord OGG link queues as MP3, stays queued on Enter, and
  hides video clipping controls.
- Real local fixture: OGG/Opus download through yt-dlp, MP3 conversion through
  ffmpeg, file-endpoint delivery, and decoding of the delivered MP3 all pass.
- A live Discord download remains unverified because only a message URL was
  supplied, not a current signed attachment URL.
